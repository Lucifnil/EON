- `eon-ui-reference.png`：界面视觉、层级与布局参考。图中的“SO 启动器”必须改为 `EON`。

## 主提示词

你是一名资深 Android 工程师与移动端 UI 设计工程师。请在当前仓库中完整设计并实现一个名为 **EON** 的 Android App。不要只输出示例、伪代码或静态效果图；交付必须是能够构建、安装和运行的完整 Android Studio 工程。

### 1. 产品目标

EON 是一个 Root 环境下的本地 `.so` 可执行文件启动器：

1. 使用 Root 权限扫描 `/data/adb` 当前目录内的 `.so` 文件，不递归扫描子目录。
2. 显示文件名、完整路径、可执行状态和最近运行状态。
3. 用户选择一个 `.so` 后，可以选择已有密钥或输入新密钥并启动它。
4. 密钥通过目标进程的标准输入 stdin 传入，绝对不能拼接到 Shell 命令、命令行参数、日志或异常信息中。
5. 输入过的密钥可以安全保存、自定义名称、编辑、删除，并能用于任意 `.so`，不要强制把密钥绑定到单个文件。
6. 显示目标进程的实时标准输出、错误输出和退出码，并支持停止进程。

本 App 不需要联网，不应申请网络权限。

### 2. 技术栈

- Kotlin。
- Jetpack Compose，不使用传统 XML View 作为主要 UI。
- Material 组件只作为基础设施，不要呈现明显的 Material Design 外观。
- `minSdk 26`，`targetSdk 36`，使用当前环境可用且彼此兼容的稳定依赖。
- 页面分页使用 Compose `HorizontalPager` 和同一个 `PagerState`。
- 使用清晰的 UI、domain、data 分层；状态由 ViewModel 和 StateFlow 管理。
- 所有 Root、文件扫描和进程 I/O 必须在后台线程或协程执行，不能阻塞主线程。
- 必须能离线或按仓库现有依赖条件可靠构建，不要留下缺失的占位类。

### 3. 视觉标准

严格参考随提示词提供的 `eon-ui-reference.png`，但把标题统一改为 **EON**。

整体风格：克制、干净的 Apple/iOS 风格，而不是彩色壁纸式玻璃拟态。

- 页面背景为纯白或极浅暖灰，例如 `#F7F7F9`。
- 主文字接近黑色，辅助文字使用 iOS 风格中性灰。
- 全局唯一主题色为 iOS System Blue `#007AFF`。
- 不使用紫色、青紫渐变、彩虹高光、霓虹光、大片彩色背景或 Material 主题色。
- 内容区域保持足够留白，排版紧凑但不拥挤。
- 普通文件列表、密钥列表使用白色 grouped list/card；它们不是玻璃。
- 圆角使用连续曲率风格，阴影非常轻。
- 支持浅色模式。首版可以不实现深色模式，但代码结构不能阻止后续加入。

### 4. 真正的液态玻璃

不能用半透明白色背景冒充玻璃，也不能只对组件自身调用普通 blur。

液态玻璃只用于：

1. 底部悬浮分页栏。
2. 启动 `.so` 的 Bottom Sheet。
3. 少量必要的悬浮按钮。

玻璃必须包含：

- 对背后内容进行实时 backdrop sampling 和 blur。
- 中性的半透明白色 tint。
- 细微的边缘高光、内描边和深度阴影。
- Android 13+ 上具有克制的折射、lens distortion 或边缘 displacement。
- 按压/拖动时具有轻微的高光或折射变化，不能夸张。
- 列表内容从底栏后方滚过时，底栏内部能真实看到被模糊和轻微折射的内容变化。

实现前请研究并优先评估以下开源方案的实际源码与最新 API，不要凭名字猜用法：

- `Kyant0/AndroidLiquidGlass`（Backdrop）：用于 Android 13+ 的真实液态折射。
- `chrisbanes/haze`：用于可靠的 backdrop blur 和旧系统降级。

如果完整液态折射在某些版本不可用：

- Android 13+：完整 backdrop blur、折射、边缘高光。
- Android 8–12：降级为可靠的实时 backdrop blur、白色 tint、描边和阴影。
- 低端设备或系统关闭相关效果时必须正常显示，不能出现黑块、闪烁或透明内容不可读。

玻璃效果的实现必须封装成可复用的 `EonGlassSurface`/Modifier，并集中管理质量档位和版本判断。

### 5. 页面结构与横向分页

主界面有三个一级分页：

1. **文件**
2. **密钥**
3. **日志**

要求：

- 三页使用 `HorizontalPager`，支持手指左右拖动切换。
- 点击底部标签时平滑滚动到对应页面。
- 拖动过程中，底部选中胶囊、图标颜色或高光位置必须跟随 pager offset 连续插值移动，而不是松手后突然切换。
- Pager 与底栏始终双向同步。
- 页面切换后保留滚动位置、搜索文字和表单状态。
- 系统屏幕边缘的返回手势优先于分页拖动；不要破坏 Android 原生预测性返回。
- 底栏悬浮在内容上方，页面内容可以滚动到底栏后面，从而展示真实玻璃模糊。

### 6. 文件页

顶部：

- 大标题 `EON`。
- Root 状态：`Root 已连接`、`等待授权`、`Root 不可用`。
- 右上角设置入口。
- 搜索框：`搜索 .so 文件`。

文件列表：

- 固定扫描 `/data/adb` 当前目录，不读取任何子目录。
- 每项显示文件名、完整路径、是否可执行、最近运行时间或退出状态。
- 支持下拉刷新或明确的扫描按钮。
- 搜索按文件名与路径过滤。
- 扫描中、空列表、Root 被拒绝和扫描失败均需有独立状态。
- 点击文件打开启动 Bottom Sheet。

不要擅自给文件添加执行权限。不可执行时应明确提示，由用户决定如何处理。

### 7. 启动 Bottom Sheet

使用参考图中的白色液态玻璃面板，支持向下拖动关闭，并包含：

- 标题：`启动 <文件名>`。
- 当前文件完整路径。
- 与输入框等宽的 `手动输入 / 已保存密钥` 分段选择器。
- 手动输入时显示密码输入框；使用已保存密钥时只显示等宽的密钥选择框，两者不同时出现。
- 手动输入并启动后自动保存，以 `yyyyMMdd_HHmm` 命名；内容相同的密钥不重复记录。
- 每个 `.so` 记住上次使用的密钥；未启动过的文件默认进入手动输入模式。
- 面板打开时直接完全展开，不要求用户再次上滑。
- 可选启动参数输入框。
- 可选工作目录选择或输入框，默认使用目标文件所在目录。
- 蓝色实心主按钮 `启动`。

启动前验证目标路径仍存在、位于允许的扫描目录内，并正确处理路径中的空格和单引号，防止 Shell 注入。

### 8. 密钥页

- 标题 `密钥库`。
- 副标题 `可用于任意 SO 文件`。
- 右上角蓝色加号。
- 每个密钥项显示自定义名称和隐藏后的密钥圆点，不显示明文。
- 支持新增、重命名、修改内容、删除和选择使用。
- 查看或编辑密钥时可以要求设备身份验证；如果首版不实现生物识别，至少保留清晰的扩展接口。
- 禁止密钥进入剪贴板历史、日志、崩溃信息或无加密备份。

密钥使用 Android Keystore 生成不可导出的 AES-256 密钥，并以 AES-GCM 加密后存储。每条记录使用独立随机 IV，禁止复用 IV。应用备份和设备迁移不得导出密钥数据库。

### 9. 日志页

- 显示当前进程状态、文件名、启动时间、实时 stdout/stderr 和退出码。
- 支持停止进程、复制非敏感日志和清空日志。
- 限制内存日志长度，长输出使用环形缓冲或分页，避免 OOM。
- 任何情况下都不能显示、保存或复制密钥。
- 启动失败时给出用户能理解的错误，如无 Root、权限不足、ABI 不兼容、目标不是可执行 ELF、动态链接器错误等。

### 10. Root 与进程执行安全

- 使用 `su` 获取 Root；正确处理 Magisk 等 Root 管理器的授权等待、拒绝和超时。
- 扫描使用安全转义后的命令或受控参数，不执行来自文件名、用户输入或日志内容的任意 Shell 片段。
- 启动参数需要经过明确的 token 化/转义策略；不要简单拼字符串。
- 密钥必须通过进程 stdin 写入，写入换行后及时清理内存中的临时副本；绝不能出现在进程参数中。
- stdout/stderr 持续异步读取，避免缓冲区阻塞导致死锁。
- 停止操作需要终止真正的目标进程及必要的子进程，而不仅是关闭 UI。
- Activity 销毁或页面切换时不能泄漏进程、线程、文件描述符或协程。
- 不要自动 chmod、移动、覆盖或删除 `/data/adb` 中的任何文件。

### 11. 原生预测性返回

- Manifest 正确启用预测性返回。
- Android 13+ 使用官方预测性返回 API 或 Compose 对应 API。
- 关闭启动 Bottom Sheet 时，返回进度应驱动 Sheet 的位移、圆角或遮罩渐变。
- 在二级设置页返回时预览前一页。
- 在主分页根页面返回时交给系统执行 back-to-home 动画。
- Android 8–12 保持传统返回行为。
- 不要使用会吞掉系统边缘返回手势的全屏手势监听器。

### 12. 设置页

设置入口位于文件页右上角，不占用底部分页：

- 扫描目录固定显示为 `/data/adb`，并注明仅扫描当前层级。
- 玻璃质量：自动、完整、节能。
- 显示版本信息与 Root 环境说明。
- 对危险路径输入给出验证，不允许空路径或相对路径。

### 13. App 图标

严格参考 `eon-icon-reference.png`，但请重绘为干净、确定性的矢量资源：

- 白色背景。
- 单一 `#007AFF` 蓝色。
- 外层为圆角正六边形线框。
- 内层为断开的六边形核心，使用少量连接线体现模块和控制流。
- 纯线条、等粗、圆角端点。
- 不出现字母 E、EON、播放键、钥匙、文件、锁或终端符号。
- 无渐变、无霓虹、无立体块面。
- 制作 Android Adaptive Icon：独立 foreground/background，保证圆形、圆角矩形、方形等遮罩下都不裁切。
- 同时提供 monochrome layer，支持 Android 13 主题图标。

应用展示名称、启动器名称和界面标题全部使用 `EON`。

### 14. 动画与交互细节

- 使用自然、克制的 spring 动画。
- 列表点击、按钮按压提供轻微缩放与透明度反馈。
- Bottom Sheet 展开和关闭流畅，不跳帧。
- Pager 拖动时底栏选中状态实时跟手。
- 尊重系统“移除动画”或减少动态效果设置。
- 触控区域至少 48dp，文本支持系统字体缩放，关键控件提供 contentDescription。

### 15. 交付要求

完成后必须：

1. 运行完整 Debug 构建并生成可安装 APK。
2. 运行 Lint 和现有测试，修复错误，不通过时不能声称完成。
3. 为 Root 命令转义、密钥加解密、分页状态和日志脱敏编写单元测试。
4. 提供 README，说明 Root 前提、`.so` 必须是可执行 ELF、构建方法、密钥安全模型、兼容范围和已知限制。
5. 给出 APK 的实际路径。
6. 不提交 build 缓存、签名密钥或任何真实密钥。
7. 不要保留旧版“SO 启动器”名称、紫色主题或伪玻璃实现。

开始编码前，先检查当前仓库并简短列出准备修改的架构和依赖。随后直接完成实现，不要在每个普通技术选择上反复询问。只有会明显改变上述产品行为的缺失信息才需要提问。

## 验收与修复提示词

请对刚完成的 EON Android 工程进行一次严格的发布前审查和修复，不要只给审查报告；发现问题后直接修复并重新验证。

重点逐项检查：

1. 底栏是否是真正的 backdrop blur，而不是透明白色；滚动内容经过其后方时是否能看到动态模糊变化。
2. Android 13+ 是否存在克制的折射/边缘高光，Android 8–12 是否安全降级。
3. 文件、密钥、日志是否通过 HorizontalPager 左右拖动，底栏选中状态是否随手势连续移动。
4. 系统边缘返回是否仍优先，预测性返回是否能正确预览退出、关闭 Sheet 和返回设置页。
5. 全部页面是否使用白色/浅灰背景、`#007AFF` 单一主题色，是否残留紫色、彩色壁纸或玻璃卡片滥用。
6. 应用名、标题、Manifest label 是否全部为 EON。
7. 图标是否为参考图中的蓝色六边形纯线条，并具备 adaptive foreground/background 和 monochrome。
8. Root 扫描和执行是否存在命令注入、路径转义或权限误修改问题。
9. 密钥是否只通过 stdin 传入，是否可能出现在 argv、日志、剪贴板、备份、异常或状态恢复数据中。
10. stdout/stderr 是否同时异步读取，长日志是否有容量限制，停止进程是否真正有效。
11. Android 8、12、13、当前 target SDK 的版本分支是否会因直接引用新 API 而崩溃。
12. 运行测试、Lint 和 Debug 构建，报告真实结果以及最终 APK 路径。

验收不通过的项目必须修复；不要使用 Lint baseline、全局 suppress 或关闭检查来掩盖问题。
